动态链接器

1. 介绍

动态链接器（在 Linux 中通常是 ld-linux.so）是操作系统的一个核心组件，负责在程序运行时加载和链接程序所依赖的动态库（Shared Libraries，如 .so 文件）。

2. 对比

特性 动态链接器（ld-linux.so） 静态链接器（ld）
工作阶段 程序运行时加载库 程序编译时将库代码嵌入可执行文件
库依赖 需要外部 .so 文件 无需外部库，所有代码在可执行文件中
内存占用 多个程序共享同一库，节省内存 每个程序独立占用内存
灵活性 可更新库而不重新编译程序 库更新需重新编译程序

3. 场景示例

  • libmymath.so：动态库，提供add()函数
  • test.c：源文件，使用add()函数
  • test：可执行程序

4. 作用

4.1 加载动态库

  • 当运行 ./test 时，动态链接器会查找并加载 test 依赖的所有动态库（如 libmymath.so、libc.so 等）
  • 如果库未找到，程序会报错
  • 动态链接器按以下顺序查找动态库：
    1. DT_RPATH 或 DT_RUNPATH（编译时通过 -Wl, -rpath= 设置）
    2. LD_LIBRARY_PATH（用户环境变量）
    3. /etc/ld.so.cache（系统缓存，由 ldconfig 生成）
    4. 默认路径（如 /lib、/usr/lib）

4.2 符号解析与重定位

  • 将程序调用的函数（如 printf、自定义函数）绑定到动态库中的实际地址
  • 例如：test 调用了 libmymath.so 中的 add() 函数，动态链接器会找到 add() 在内存中的位置并建立关联

5. 符号解析（Symbol Resolution）

5.1 目标

  • 确定程序中引用的符号（如函数名、全局变量）在动态库中的实际地址

5.2 步骤

  1. 程序启动时

    动态链接器加载可执行程序（如 test）和它依赖的动态库（如 libmymath.so）

  2. 构建符号表

    • 动态链接器会扫描所有加载的库（包括 libc.so、libmymath.so 等），收集它们的导出符号表（即库提供的函数和变量）

    • 同时，记录程序的未解析符号（即程序需要但尚未绑定的符号，如 add()）

  3. 符号匹配

    • 动态链接器在所有已加载的库中查找未解析符号的定义

    • 例如：程序 test 调用了 add()，动态链接器在 libmymath.so 的符号表中找到 add 的地址，如果找不到符号，会报错

  4. 处理重复符号

    如果多个库定义了相同符号（如两个库都有 add()），默认选择最先加载的库中的符号（可通过 LD_PRELOAD 覆盖）

6. 重定位（Relocation）

6.1 目标

  • 将程序中对符号的引用（如 call add）替换为实际的地址

6.2 步骤

  1. 重定位表（Relocation Table）
    • 可执行文件和动态库中都有一个重定位表（.rel.plt、.rel.dyn 等），记录了哪些地方需要修正地址
    • 例如：
      • 当 test 调用 add() 时，编译后的指令可能是 call 0x0（临时占位地址）
      • 重定位表会标记这条 call 指令需要被修正为 add 的真实地址
  2. 修正地址
    • 动态链接器根据符号解析的结果，将程序中的占位地址替换为实际地址
    • 例如：
      • 假设 add 在 libmymath.so 中的地址是 0x7ffff7e3d000
      • 动态链接器将 call 0x0 修改为 call 0x7ffff7e3d000
  3. 延迟绑定（Lazy Binding）
    • 为提高性能，动态链接器默认采用延迟绑定
      • 首次调用函数时，通过 PLT 和 GOT 动态解析地址，后续调用直接跳转到已解析的地址
      • PLT（Procedure Linkage Table，过程链接表）：存储跳转到动态库函数的跳转指令
      • GOT（Global Offset Table，全局偏移表）：存储动态库函数/变量的实际地址
      • PLT 通过 GOT 间接跳转到目标函数
    • 可通过 LD_BIND_NOW=1 禁用延迟绑定（启动时解析所有符号）

7. 示例说明

7.1 场景

  • libmymath.so：动态库，提供add()函数
  • test.c：源文件，使用add()函数
  • test：可执行程序

7.2 编译

  • gcc test.c -o test -L. -lmymath

    • -L.：告诉编译器在当前目录找 libmymath.so

    • -lmymath：链接 libmymath.so

  • 编译器生成 test，但 call add 的地址是临时的（如 0x0）

7.3 运行

  • 执行 ./test 时，动态链接器会：
    1. 检查 test 的依赖（如 libmymath.so）
    2. 按照搜索路径查找动态库
    3. 扫描库以收集导出符号表，并记录程序的未解析符号（如 add）
    4. 解析符号（如 add），找到它在 libmymath.so 中的实际地址（如 0x7ffff7e3d000）
    5. 将 call 0x0 修正为 call 0x7ffff7e3d000
    6. 程序正常执行
