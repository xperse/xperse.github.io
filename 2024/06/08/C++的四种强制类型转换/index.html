C++的四种强制类型转换

1. static_cast

1.1 介绍

​ 主要用于在相关类型之间进行转换，是 C++ 中最常用的类型转换运算符。

1.2 基本用法

​ static_cast<type>(expression);

1.3 用途示例

  • 基本数据类型之间的转换

  • 指针 / 引用在类层次结构中的向上转换（从派生类到基类）

  • 显式执行隐式转换（使代码意图更明确）

  • void指针与其他指针类型之间的转换

1.4 错误示例

  • 无关类型之间进行转换

  • 移除 const / volatile 限定符

1.5 注意事项

  • 比 C 风格转换更安全

    • 限制更多，不允许不安全的转换
    • 在代码中更容易搜索
    • 明确表达了程序员的意图

  • 编译时检查：static_cast 在编译时执行类型检查

  • 不能用于无关类型指针之间的转换（如 int* 转 double*）

  • 不能移除 const / volatile 限定符（需要使用 const_cast）

  • 向下转换（从基类到派生类）是允许的，但不安全

    • static_cast 在编译时执行转换，不会检查指针或引用所指向的对象的实际类型。如果基类指针/引用实际指向的对象不是目标派生类，转换后的指针/引用会导致未定义行为（如内存越界、非法访问等）
    • 仅检查基类和派生类之间是否存在继承关系（否则编译报错），不会检查指针实际指向的对象是否匹配目标类型
    • 仅当能100%确定指针或引用实际指向的是目标类型时，才能安全使用

  • 不能用于多态类型的向下转换（这种情况下应使用 dynamic_cast）

    • 缺乏运行时类型检查（RTTI）

2. reinterpret_cast

2.1 介绍

​ 只是简单地将一种类型的位模式重新解释为另一种类型，是 C++ 中最强大但也最危险的类型转换方式。

2.2 基本用法

​ reinterpret_cast<type>(expression);

​ 注：type 和 expression 中必须有一个是指针或引用类型（也可以两个都是指针或引用）

2.3 用途示例

  • 指针类型之间的转换

  • 不同类型引用之间的转换

  • 整数与指针之间的转换

  • 函数指针之间的转换

2.4 注意事项

  • 最危险的转换：reinterpret_cast 是 C++ 中最强大但也最危险的类型转换方式
  • 不进行运行时检查：它不会进行任何类型安全检查或运行时检查
  • 不能用于移除 const / volatile 限定符（应使用 const_cast）
  • 不可移植性：使用 reinterpret_cast 的代码可能在不同平台或编译器上表现不同
  • 潜在未定义行为：许多情况下使用它会引发未定义行为
  • 最后手段：只有在确实需要且了解所有后果时才使用

3. const_cast

3.1 介绍

​ 主要用于添加或移除变量的 const 或 volatile 属性。

3.2 基本用法

​ const_cast<type>(expression);

​ 注：type 必须是指针、引用或指向对象类型成员的指针

3.3 用途示例

  • 添加 / 移除变量 const 限定符

  • 添加 / 移除变量 volatile 限定符

3.4 注意事项

  • 不能用于不同类型间的转换
  • 不应修改原本就是 const 的对象
  • 应当谨慎使用，因为它可能破坏类型系统的安全性

4. dynamic_cast

4.1 介绍

​ 主要用于在继承层次结构中进行安全的向下转型和交叉转型。

4.2 基本用法

​ dynamic_cast<type>(expression);

​ 注：type 和 expression 必须是指针或引用

4.3 用途示例

  • 向下转型（指针）

  • 向下转型（引用）

  • 交叉转型

4.4 注意事项

  • 性能开销：dynamic_cast 比 static_cast 有额外的运行时开销

  • 运行时检查：dynamic_cast 会在运行时检查转换的有效性

  • 多态要求：基类必须有虚函数（通常有虚析构函数），以启用 RTTI

  • 安全性：如果转换失败，对于指针会返回 nullptr ，对于引用会抛出 std::bad_cast 异常

  • 向下转型：前提必须要是安全的，要借助RTTI进行检测，所以只能部分成功

    • 当使用 dynamic_cast 对指针进行类型转换时，程序会先找到该指针指向的对象，再根据对象找到当前类（指针指向的对象所属的类）的类型信息，并从此节点开始沿着继承链向上遍历。如果找到了要转换的目标类型，那么说明这种转换是安全的，就能够转换成功；如果没有找到要转换的目标类型，那么说明这种转换存在较大的风险，就不能转换
    • 安全场景：当基类的指针指向派生类对象或基类是派生类对象的引用时，再向下转型才是安全的
    • 从本质上讲，dynamic_cast 还是只允许向上转型，因为它只会向上遍历继承链。造成允许向下转型这种假象的根本原因在于，派生类对象可以用任何一个基类的指针指向它，这样做始终是安全的
