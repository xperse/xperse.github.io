C语言中的动态内存管理

在 C/C++ 动态内存管理中，malloc、calloc 和 realloc 是三个最核心的函数。它们的核心区别在于初始化、参数和用途。

1. 核心区别

函数 参数 初始化 返回值 主要用途
malloc (字节数) 不初始化（脏数据） 指向分配内存的指针 申请新内存块
calloc (个数, 单个大小) 初始化为 0 指向分配内存的指针 申请并清空内存（如数组）
realloc (旧指针, 新字节数) 不初始化（保留旧数据） 可能改变的新指针 调整已存在内存块的大小

2. 详细解析

2.1 malloc（内存分配）

  • 原型：void *malloc(size_t size);
  • 行为：从堆区分配 size 个字节的连续内存。
  • 关键点：它不会清空内存，里面可能是上一次使用留下的随机值（“脏数据”）。因此，申请后必须手动初始化，否则读取会引发未定义行为。
  • 典型场景：当你即将把文件数据或计算数据完整写入这块内存时，使用 malloc 效率最高（因为省去了清零的时间开销）。

2.2 calloc（计数分配 + 清零）

  • 原型：void *calloc(size_t num, size_t size);
  • 行为：分配 num * size 个字节的内存。
  • 关键点：它会将分配的所有内存位初始化为 0。这不仅是便利，更是安全的保障（尤其防止敏感数据残留）。
  • 注意：由于有清零步骤，calloc 比 malloc 稍慢。但现代编译器对 calloc 有专门优化（如使用写时复制零页），对于大块内存，效率差距并不明显。
  • 典型场景：分配结构体数组，需要确保所有成员初始为 NULL 或 0 时。

2.3 realloc（重新分配）

  • 原型：void *realloc(void *ptr, size_t new_size);
  • 行为：调整先前 ptr 指向的内存块大小到 new_size 字节。
  • 关键点（最容易踩坑）：
    • 数据保留：原内存中的数据会被复制到新位置（取新旧大小中较小的字节数）。
    • 地址可能变：如果当前内存块后面有足够空间，就在原地扩展（地址不变）；如果不够，系统会找新地址并拷贝数据，原指针自动失效。
    • 必须接返回值：ptr = realloc(ptr, new_size); 是错误写法！如果扩展失败返回 NULL，原指针就丢失了（内存泄漏）。正确写法是先用临时指针接收，判断成功再赋值。

4. 关于“失败”和“释放”的共性

  • 失败返回：三个函数分配失败时，都返回 NULL（realloc 例外是返回 NULL 且原内存不变）。
  • 释放规则：三者申请的内存都必须用 free(ptr) 释放，且释放后记得将 ptr = NULL，防止“野指针”。
  • 关于 realloc(ptr, 0)：等同于 free(ptr) 并返回 NULL，但建议不要依赖这种写法，直接使用 free 更清晰。

5. 场景选择

  • 需要新申请内存，且数据马上写入 → 用 malloc（最快）。
  • 需要新申请内存，且要求初始为全零（如字符串、安全结构） → 用 calloc。
  • 数组或缓冲区动态扩容/缩容 → 用 realloc（并严格遵守“临时指针”写法）。
